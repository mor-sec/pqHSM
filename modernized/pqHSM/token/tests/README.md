# Characterization tests: TPM sealing (Phase 2, slice 1)

These tests define "done" for the TPM part of `pqhsm-token`. They record what the legacy C
code **does** (`src/fhsm_tpm.c` through the `FHSM_TPM_TEST_HOOKS` seam, and
`src/fhsm_token_tpm.c`), not what its comments say. Two places expect non-C behaviour, both
approved in `analysis/pqHSM/DIVERGENCES.md`. Each test asserts C's result first:

- **DIV-015(d)**, `companion_seal_fsyncs_the_tmp_before_renaming_div015`: C renamed an
  un-fsyncable `.tpm.new` (a staged FIFO) into place and returned OK. Since DIV-031(b) the
  FIFO is removed before the tmp is created, so this row now seals normally.
- **DIV-031(b)**, `companion_seal_does_not_follow_a_link_at_the_tmp_div031`: C wrote the
  sealed blob through a link planted at `.tpm.new`.
- **DIV-017**, `an_unrelated_fork_during_a_seal_inherits_no_memfd_div017`: C's unrelated
  child saw all four seal memfds, including the DEK. The probe tests allow the tpm2 child's
  inherited set to shrink, down to the memfds its own argv names.
  `hooks_cmd_is_run_through_sh_like_c_div017` pins the half of DIV-017 that stays the same.

Like `tests/tpm2-stub.sh`, these tests prove the plumbing on our side of the CLI and nothing
about the TPM itself.

## Running

From `modernized/pqHSM`:

```sh
podman run --rm --cap-drop=DAC_OVERRIDE,DAC_READ_SEARCH \
    -v $PWD:/ws:Z -v <cargo-registry>:/opt/rust/cargo/registry:Z -w /ws \
    localhost/pqhsm-rust:1.99.1 cargo test -p pqhsm-token
```

- **`--cap-drop` is required.** Root in the container can read a mode-000 file, and the
  goldens were made without that capability. Without the flag, the 2 "unreadable companion"
  tests fail with a message that says so.
- **The C ABI tests** (`tpm_ffi.rs`, `tpm_ffi_no_tpm.rs`) compile only with
  `--features ffi`. Each file is its own process, because the C ABI caches availability for
  the whole process. Once slice 3 makes `ffi` import C symbols, run them from the hybrid
  build instead.
- **The `/var/lib/freehsm/tpm` test** is `#[ignore]` because it writes outside the temp dir.
  In a throwaway container, add `-- --include-ignored`.
- **Feature `tpm-test-hooks`** is turned on for the tests by the crate's dev-dependency on
  itself (`Cargo.toml`). Dev-dependencies never reach the shipped staticlib.

While `src/lib.rs` is still a stub, every test that calls into it panics with
`not yet implemented: RULE-089: …`. The ffi tests abort their process on the first call,
because a panic cannot unwind out of `extern "C"`.

## Layout

| File | What it pins |
|---|---|
| `tpm.rs` | every row of `golden/tpm/cases.tsv` through the safe API, the DIV-015/DIV-017 tables, and the meta-test |
| `tpm_ffi.rs` | NULL-argument rows (`ffi_*`) and marshalling through the C ABI, TPM present |
| `tpm_ffi_no_tpm.rs` | the C ABI with no device: availability is checked before the arguments |
| `common/mod.rs` | golden reader, stub fixture (`Fx`), log and probe normalisers, companion-file fixtures |
| `golden/tpm/` | generated by `tests-support/golden/regen_tpm.sh`. Do not edit by hand |

### `golden/tpm/`

- `cases.tsv` has one row per case: `case`, `op`, `rv`, then `key=value` columns.
  - `rv` is `0x%x` for `fhsm_rv_t` functions, and the decimal `int` for the others (`-` for `unlink`).
  - Inputs: `env` (stub knobs, as shell assignments), `cmd`, `cmd_prefix`, `stub=probe`,
    `device=absent|dir`, `pre=not_available_yet`, `cap`, `blob_in`, `tok=plain|nodir|len:N`,
    `pre=<companion state>`, `value_hex`, `a`/`b`.
  - Outputs: `blob`, `out` (the caller's 32-byte buffer, pre-filled `cc`), `out=untouched`
    (seal buffer, pre-filled `ee`), `after_tpm`/`after_tmp`/`after_tok`
    (`absent|dir|fifo|file:MODE:HEX`), `drained`, `startup_calls`, `seen`, `tpm_dir`.
- `log/CASE.txt` is the stub's `FHSM_TPM_FAKE_LOG`. The tests compare it after renaming each
  `/proc/self/fd/N` to `fd#k` by first appearance, and they fail on any other absolute path
  (#109).
- `probe/CASE.txt` holds, per child, the argv with memfd names in place of paths, the
  child's fd 1 and fd 2, and the fhsm memfds it inherited.
- `input/CASE.hex` holds the bytes placed in `{tok}.tpm` before the call.
- `tpm2-stub.sh` (copied from `tests/`) and `tpm2-probe-stub.sh` (copied from
  `tests-support/golden/`) are the exact stubs the goldens were made with. The tests run
  these copies.

The secret is the invented pattern `0x00..0x1f`. No value from the legacy tree is a fixture.

## Adding a case

1. Add a `run(...)`, `SEAL(...)`, `UNSEAL(...)` or `TOK(...)` line to `main()` in
   `tests-support/golden/gen_tpm.c`. Give any new input a column the runners can rebuild
   from (`common/mod.rs` `Fx::tpm`, `tok_for`, `prepare`).
2. Run `tests-support/golden/regen_tpm.sh`. It needs podman and `localhost/freehsm-build:1.2.0`.
3. Name the row in a test, usually one line in a `golden!` table in `tpm.rs`.
   `every_golden_row_is_covered_by_a_named_test` fails until you do.
4. If Rust is meant to differ, register a DIV first, then add the row to the `DIV015`- or
   `DIV017`-style table, so the test asserts C's value before it asserts Rust's.

# Characterization tests: the token store (Phase 2, slice 3)

These tests define "done" for `src/fhsm_token.c` (the 43 functions of `include/fhsm_token.h`).
They record what the legacy C **does**. All C values come from running the legacy C
(`tests-support/golden/gen_store.c`, linked against the real `fhsm_token.c` and
`fhsm_crypto.c`) and from the slice-0 corpus (`modernized/pqHSM/testdata/`, made by `gen_token.c`).

## Running

From the repository root (same container rules as above, `--cap-drop` included):

```sh
R=localhost/pqhsm-rust:1.99.1
run() { podman run --rm --cap-drop=DAC_OVERRIDE,DAC_READ_SEARCH -v $PWD:/repo:z \
          -v <cargo-registry>:/opt/rust/cargo/registry:z -w /repo/modernized/pqHSM $R "$@"; }
run cargo test --offline -p pqhsm-token                  # openssl-sys crypto backend
run cargo test --offline -p pqhsm-token --features ffi   # C crypto seam + the C ABI tests
run cargo test --offline -p pqhsm-token --test scenarios init_fresh   # one scenario
```

- The whole repo is mounted, not only `modernized/pqHSM`, because the meta-tests read
  `analysis/pqHSM/DIVERGENCES.md` and `PHASE2_PLAN.md`.
- With `--features ffi`, `crypto.rs` runs against the C seam. The C primitives are replaced by
  the doubles in `store_common/c_doubles.rs` (`fhsm_pbkdf2`, `fhsm_aes_gcm_*`,
  `fhsm_rng_bytes`, secure heap, `fhsm_api_free_value`, a non-variadic `fhsm_audit_event`).
  Both backends are checked against the same C-recorded vectors (`kat.tsv`). The hybrid build
  links the real C instead.
- **While `src/` is a stub**, every test that calls in panics with
  `not yet implemented: RULE-…`. The meta-tests pass. `token_ffi.rs` aborts its process
  (SIGABRT) on the first call, after printing `not yet implemented`: a panic cannot unwind out
  of `extern "C"`.

## Layout

| File | Tests | What it pins |
|---|---|---|
| `scenarios.rs` | 124 + 7 meta | each scenario of `store_scenarios.txt`, step by step against C, and the `DIVS`/`DIV024` tables |
| `header.rs` | 10 | the 317-byte header: offsets, round trip, every refusal (RULE-004, DIV-011) |
| `store.rs` | 9 | v1–v4 readers (every crafted plaintext gets C's verdict), the v4 writer byte for byte, frame, public view (RULE-003, 044, 088) |
| `corpus.rs` | 3 | every slice-0 corpus token loads with C's manifest verdicts; `migrate_zero_dek` (DIV-010) |
| `crypto.rs` | 5 | PBKDF2 / GCM / DRBG seam against C's values, including the 1000-iteration floor |
| `token_props.rs` | 7 | timing, locks, ordering, fork: throttle ladder, DIV-012 across two handles, H4, M3, M4 |
| `token_ffi.rs` | 4 | (`ffi` only) `ffi.tsv`, C's NULL/size-query/marshalling answers through the C ABI; M2; DIV-027 |
| `token_rng_ffi.rs` | 5 | (`ffi` only) DIV-025: every DRBG draw of init, init_user_pin, set_pin, reinit and an object write, failed in turn |
| `store_common/` | – | golden readers, PINs, the Rust-only rows (`RUST_ONLY`), the Rust scenario interpreter (`scenario.rs`), C doubles (with a DRBG failure knob) |
| `golden/store/` | – | generated by `tests-support/golden/regen_store.sh`. Do not edit by hand |

### `golden/store/`

- `store_scenarios.txt` is a copy of `tests-support/golden/store_scenarios.txt`.
  `the_goldens_were_made_from_the_current_script` fails if the copy is stale.
- `steps.tsv`: one row per step, `scenario`, `step`, `line`, then C's output. Every op line
  also carries one `audit=event/ROLE/rv/params` per audit record C wrote.
- `tok/NAME.tok`: the token file at the end of scenario NAME (the `from=tok:` starts).
- `pt/SCEN.STEP.bin` / `pub/SCEN.STEP.bin`: the decrypted blob plaintext and the clear public
  section at each `snap`. These are compared byte for byte.
- `in/*.bin`: crafted plaintexts (v1–v4, every bounds case). `kat.tsv`: crypto vectors.
  `ffi.tsv`: C-ABI rows. `SHA256SUMS`: everything above.

**Masked** (both sides do it the same way): the serial (shape only: `serial=ok`), salts,
nonces and ciphertext (provenance against the previous `snap`: `same`/`new`/`zero`), and the
remaining throttle (rounded up to the 500 ms × 2^n ladder). The `fhsm_token_label` overrun
of a 64-byte label is printed as `+overrun:serial` instead of the serial bytes.
**Pinned**: every other header byte, the ciphertext length, the plaintext and public section,
the file set and modes, and every audit record's event, role, rv and params.

**Secrets.** Every PIN is invented (`store_common/mod.rs`: `SO_PIN`, `USER_PIN`, `WRONG_PIN`,
`NEW_PIN`, and the `lit:` PINs in the script). Nothing comes from the legacy tree or its tests.
Key material is generated, or a counting pattern.

## Where Rust is expected to differ

Each row of `DIVS` and `DIV024` (`scenarios.rs`) names a step. The test checks that the golden
still has C's value there (`c`) before it checks Rust's (`rust`). `rust` is a pattern, or
`C~OLD~>NEW`: C's output with OLD replaced by NEW, compared exactly (used where only one value
in a long line differs). `same_file_as` says which step's file image must be unchanged.
`every_div_row_names_a_golden_step_and_pins_c` (one row per step; OLD must be in C's golden)
and `the_div_table_matches_divergences_md` keep the tables honest.

Divergences no golden can show (C's side is undefined, or needs a DRBG failure the generator
never has) are the Rust-only rows of `store_common::RUST_ONLY`: each names its test, the C lines
it covers and what C does. `rust_only_rows_name_real_tests_and_cover_every_rng_site` checks
the test exists and that the DIV-025 rows cover every line DIVERGENCES.md lists.

**DIV-023 value format.** Each TPM record's key carries the record's own rv as C's `0x%x`
(lowercase hex, no padding; the `rv=0x%x` of `src/fhsm_audit.c`): `"0x0"` on seal and unseal
success, `"0x6"` for a failed seal or unseal (the TPM step's code), `"0x30"` for
`tpm-dek-mismatch`, `"0x80000005"` for `tpm-required-but-missing`. C's goldens show
`"INVALID"`, the generator's rendering of the value C read past `FHSM_AUDIT_END`.

**DIV-024 scope.** Only a plaintext that GCM authenticates and `parse_objects` refuses
(`:1006`). Frame failures (`header_plus_10_bytes`, `blob_ct_len_*`, truncation) never reach
GCM and are still pinned as C: the login succeeds with no objects.

**DIV-025 injection.** With `ffi`, the crypto seam draws through `fhsm_rng_bytes`, which in
tests is the double in `store_common/c_doubles.rs`. `RNG_FAIL_AT` fails one draw with
`FHSM_RV_RNG_FAILURE` (0x80000008) and leaves the buffer as it was. Each test counts a clean
call's draws (with a floor per operation) and fails each in turn, so it covers every site
without assuming the order.

Deferred rules are pinned as C does them: RULE-082/005 (`set_pin_*`), RULE-083
(`login_user_pin_not_initialized_rule083`, `locked_before_uninitialized_rule083`),
RULE-086/056 (`logout_keeps_objects_rule086`), RULE-084 (throttle), RULE-090–092 (objects),
RULE-036/079(a) (PIN minimums), RULE-003(1) (`BLOB_MAX` above `INT_MAX`).

Error code when a failing call's audit also fails (decided 2026-10-31): the original error
wins and the state is unchanged (`audit_fail_tpm_seal_failure_div001` step 4: 0x6). A call that
would otherwise succeed returns 0x30 (DIV-001, H4).

## Not covered

- Real TPM hardware, as in slice 1. The stub decides every TPM answer.
- `RULE-003(1)`: a `ct_len` near `BLOB_MAX` truncated by C's `int` cast in GCM (Phase 3).
- Out-of-memory paths (`HOST_MEMORY`, secure-heap `DEVICE_MEMORY`) and `fhsm_secure_*`
  placement (#127). None of it is observable without fault injection.
- Concurrency inside one process beyond `token_props.rs` (no interleaving fuzz).
- C-ABI NULL handling for functions whose `ffi.tsv` row C itself would crash on.

## Adding a case

1. Add a `scenario` block to `tests-support/golden/store_scenarios.txt`. A new op must be
   added to both interpreters: `run_op` in `gen_store.c` and `Run::op`/`Run::token_op` in
   `store_common/scenario.rs`, with the same output format.
2. Regenerate (podman and `localhost/freehsm-build:1.2.0`; `/tmp` may be full, so point
   `TMPDIR` at disk), twice, and check that the two runs are identical:
   `TMPDIR=$PWD/modernized/pqHSM/target/tmp-slice3 modernized/pqHSM/tests-support/golden/regen_store.sh`
3. Add the name to the `scenarios!` list in `scenarios.rs`.
   `every_scenario_has_a_test_and_every_test_a_scenario` fails until you do.
4. If Rust is meant to differ, register the DIV first, name the scenario `..._divNNN`, and add
   `DIVS` rows that pin C's value at each differing step.
